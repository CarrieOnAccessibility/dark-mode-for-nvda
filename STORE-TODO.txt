4. DO THE TESTING ONLY YOU CAN DO
---------------------------------
Claude verified pixels, but you use NVDA. Before submitting, spend a few days
with it on and check by ear:
   - check boxes, radio buttons, buttons, lists, menus and combo boxes are
     announced exactly as they were before (names, "checked", positions);
   - the Add-on Store dialog, the Python console, the log viewer, the speech
     and braille viewers, the input gestures dialog, the dictionary dialogs;
   - the toggle command (assign it a gesture under Input Gestures > Dark Mode);
   - Windows High Contrast on and off while NVDA is running;
   - NVDA exit and restart, and reloading plugins (NVDA+Ctrl+F3);
   - if you can borrow a Windows 10 machine, run it there once (some of the
     colours - black title bars, the grey outline - are Windows 11 only and
     should quietly fall back on Windows 10). If not, say "Windows 11" in the
     description.
Write down anything that reads differently from before. Anything that changes
what NVDA SAYS is a bug that must be fixed before submission.


5. KNOWN LIMITATIONS TO MENTION IN THE DESCRIPTION
--------------------------------------------------
Users should know these up front (Claude can word them):
   - The little "Checking for update" progress box is a Windows-native dialog
     drawn by Windows itself on a separate thread; it stays light. Only a change
     inside NVDA can fix that (see 7).
   - Menu hover highlight is whatever Windows draws for dark menus.
   - It relies on undocumented Windows dark-mode switches; a future Windows or
     NVDA release could change how things look. It never changes what controls
     ARE, only how they are painted.
   - It should retire when NVDA gains a native dark mode (NVDA issue #16683 is
     the one to watch).


6. SUBMIT TO THE STORE  -- READY: see STORE-SUBMISSION.txt for the three steps and every field
----------------------
Submission is a GitHub issue on NV Access's "addon-datastore" repository, using
their "Add-on submission" form. You fill in: the download link (the release
file from step 2), the file's checksum (Claude computes it), licence name and
link, source link, homepage, channel, minimum and last-tested NVDA versions,
summary and description, and you tick the boxes agreeing to their terms
(essentially: it is your work, it does nothing harmful, it follows their code of
conduct). Their automated checks run within minutes; a person then reviews it.
The first submission of a new add-on can take up to two weeks; updates are
usually faster. Every new version is a new submission of the same form.
-> Needs your GitHub account. Claude can prepare every field as text for you to
   paste, but the issue has to be opened by you.
